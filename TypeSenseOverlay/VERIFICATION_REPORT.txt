Grey Board live-project cleanup verification
============================================

Source basis:
- Current live project files supplied in this conversation.

Root cause addressed:
- SDK-style Deckboard.csproj implicitly compiles every .cs file.
- Visual Studio backup files such as "AIEnhanceService - Copy.cs" and
  "ControlCenter - Copy.cs" therefore create duplicate TypeSenseOverlay types.
- This explains the large CS0229 ambiguity cascade shown in Visual Studio,
  including ambiguity between Native.ActiveTextContext.Word members.

Changes:
1. Deckboard.csproj explicitly removes "* - Copy.cs" and "* - Copy*.cs" from compilation.
2. The clean package contains only one canonical source file for each type.
3. Native.cs fixed the post-space context path: it now returns an empty current
   word plus the previous word, allowing next-word prediction instead of
   returning false because the current word is empty.
4. Added GreyBoard_CleanProject.ps1 for cleaning an existing working directory.

Static checks performed after edits:
- No duplicate canonical type declarations in the clean source directory.
- No '* - Copy.cs' files in the clean source directory.
- Deckboard.csproj is well-formed XML.
- C# delimiter balance checked across source files.
- Native.cs contains exactly one ActiveTextContext declaration.

Build verification:
- A real .NET build could not be executed in this environment because the
  .NET SDK/MSBuild tooling is not installed.
- Therefore this package is NOT claimed to be build-verified.
- On Windows, run Clean/Rebuild after extraction.

Final hardening pass: SuggestionOverlay LINQ import, strict shortcut parsing, immediate AI cancellation/invalidation, 3-character prefix index, dirty-only profile save on Stop, diagnostics env-only, and explicit duplicate-copy source exclusion.
